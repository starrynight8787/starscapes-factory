WHITE ICONS IN THE MOBILE MENU: FIX FOR "YOU CAN'T SEE THEM"   starscapes-menu-icons-22oct.zip
(One rule in one stylesheet, and a test. No Supabase step. Released through a preview first.)

THE PROBLEM (reported with a phone screenshot, 22 October 2026): in the mobile menu the little room pictures beside each room's name cannot be seen, and the Leadership Lounge and Idea Hatchery ones barely exist at all.
THE CAUSE: the pictures are navy line art on a see-through background, and the mobile menu is a dark navy gradient, so navy sits on navy. The stylesheet already had a rule for exactly this ("the navy line art needs a light backing on the dark mobile menu": a white tile behind each picture), but it was aimed at a class called sf-tile, which only an older component uses. The pictures are now drawn by a component that gives them a different class (sf-room-icon), so the rule matched nothing.

THE FIX (src/styles/site.css): one rule, .sf-menu .sf-room-icon { filter: brightness(0) invert(1) }. It draws each picture in white, the menu's own #fff (the same white as the room names beside them). The shape and the see-through background are kept, and only the colour changes, so the stars and details inside each picture stay crisp.
IT IS ONLY INSIDE THE DARK MOBILE MENU. The rooms dropdown on a computer is a white panel, and the membership pages, the room directory and the 404 page are light: they keep the navy pictures. The old white-tile rule is left where it is (harmless: it still serves the older component).

PROOF: I rendered the real menu in a browser with your built stylesheet and your real icon files, with and without the rule. Without it the pictures are barely visible (like the screenshot); with it all eight are clear white line art.
TESTS: 8 new in test/mobile-menu-icons.test.jsx (the white rule exists; it is the menu's own white; it aims at the class the picture really has, which is the bug that caused this; the mobile menu draws every room's picture; every room has its picture file; no rule whitens a picture outside the dark menu; the desktop dropdown is white and left alone; the picture's own style does not whiten it for everyone). 10 deliberate breakages, ALL caught (the filter removed, the pictures turned black, only almost white, the rule applied to the whole site, aimed at the wrong class, the desktop dropdown whitened too, the menu text colour changed, the menu no longer drawing pictures, the picture given a different class, the dropdown made dark).
