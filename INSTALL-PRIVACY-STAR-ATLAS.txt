THINGS TO KNOW
 * THE "WE DON'T LOOK" PROMISE IS YOURS TO KEEP. The policy says we could see one member's answers by looking directly in the database, but we don't. The admin page only reads the totals, so that part is safe. The rest is you: do not open the raw check-in rows in the Supabase dashboard. (Claude will not open them either: it only ever sees counts and totals.)
 * DELETING ON REQUEST WITHOUT LOOKING. The policy now promises members can ask for their check-ins to be deleted. Deleting does not need anyone to READ the answers: it is a single command that removes one member's rows by their account, without showing them. When the check-in table exists (step 2 of the Star Atlas build), ask Claude for that exact command. An even cleaner option, worth adding to the build brief: a "Delete my check-ins" button on the member's own atlas page, so nobody has to touch the table at all.
