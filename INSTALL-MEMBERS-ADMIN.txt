(No Supabase step. Nothing to do in Stripe. One thing to check in Vercel: OWNER_EMAIL and a database key are already set, because Orders uses them.)

WHAT IT DOES
The "Passes and members" box in Admin (it said "Coming soon") is now a link to /admin/members, a page for you only:
 * WHAT THE PASSES COST: the five passes by name, and the price for 1, 2, 3 and everything: a month, a year (ten months), and each on the launch offer. Read from the same rules checkout uses, so it can never disagree with it.
 * WHO HOLDS EACH PASS: how many people hold each of the five now, and how many of those have cancelled; plus the totals: holding passes now, active, cancelling, payment trouble, ended, never started.
 * THE MEMBERS: each person's email address, status in words, which passes, what they pay (with the launch offer and when it ends, or a promo code's note), when they pay next (or until when their passes stay open), and an "Open in Stripe" button.
   Filter by pass, by status, or search the emails. A banner says whether Stripe is in test or live mode (the Stripe links open that mode's customers).
 * It is for LOOKING. Cancelling, refunding and changing a card stay in Stripe, one click away.
 * "Holding passes" means the same as everywhere else on the site: active, trialing, or past_due (a payment being retried). A cancelled member still holds their passes until the period they paid for ends.

HOW IT IS KEPT SAFE
 * Email addresses are not in the members table; the server reads them from the sign-in system, only for you, each time you open the page. Nothing new is stored.
 * The request checks who is asking BEFORE it reads anything: only the owner email in Vercel (OWNER_EMAIL) with a CONFIRMED address is let in. Anyone else, signed in or not, gets a plain refusal and nothing is read.
 * A member's full account id never leaves the server (the page shows an 8-letter label only), nor does any key. A Stripe customer id is only used if it looks like one.
 * No 13th server function: it is handled inside the membership function (like the reminders), so the free Vercel plan limit of 12 is respected.
 * 70 tests, including 11 deliberate breakages (owner check removed, full id sent, unprotected route, any text passed on as a Stripe id...): all caught.
 * ALSO IN THIS PACKAGE (tests only): two Book Club tests from the genres package were left out of date by your newest commit, which draws only the first five genres as books on the Book Club page (the other 15 are on the bookshelf page's filter). They now say that. (The admin console test also no longer lists which tiles are still "Coming soon", so it stays right as each is built.)

ONE THING TO KNOW: the members table does not say whether a membership was made in Stripe's test or live mode. After you go live, the test memberships from today are still in the table until they are cleared (SFW-204 lists this), and their Stripe links will not open in live mode.

INSTALL (from the project folder; ONLY run git add . at the very end)
 1. cd ~/Website/supabase-blog-starter
 2. unzip -o ~/Downloads/starscapes-members-admin-20oct.zip
 3. python3 tools/add-members-admin.py          (it checks four files first; if anything is unexpected it changes nothing)
 4. npm test                                    (it should end with exactly 1 failed: the contact address test, which waits for the legal review)
 5. npm run build
 6. ls api/*.js | wc -l                         (it must still print 12)
 7. git add .
    git status                                   (4 changed source files, 5 new source files, 5 test files, the install notes, the installer and its test; nothing ending .before-)
    git commit -m "Admin: build the Passes and members page"
    git push
 8. When Vercel says READY, sign in as the owner, open Admin and press "Passes and members". You should see the five passes' prices, a count of who holds each (your own test membership: 1 on Come Write With Me), and your own email in the list, marked "Active", with an Open in Stripe button.
