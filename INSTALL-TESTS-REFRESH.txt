THE REAL PROBLEM: "MOST READ" CANNOT LOAD
The post_reads table (the counts behind "Most read" on Archive Entries) has a rule saying everyone may see the counts, but nobody was given permission to read the table: I checked your live database and visitors and signed-in people both come back "no". A table made in the Supabase SQL editor is not readable by the website until that permission is granted. Your project's own test (browser-tables-have-permissions) was already warning about exactly this.
 FIX, in Supabase: your project, SQL Editor (left menu), New query, paste this one line, click Run. It says "Success. No rows returned." Safe to run twice.
    grant select on public.post_reads to anon, authenticated;
 To check it, run this in a new query: both should say true.
    select has_table_privilege('anon','public.post_reads','select') as visitors_can_read, has_table_privilege('authenticated','public.post_reads','select') as signed_in_can_read;
 (The package also adds that line to sql/post-reads.sql, so a fresh copy of the database is made correctly.)
